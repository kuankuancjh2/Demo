# 莫下面一个空

> Game Jam MVP · 回合制方格 Roguelike
> 你扮演「莫」，在迷宫里穿行。带哪个偏旁走到出口，结局就定格成哪个字。

---

## 怎么跑

```bash
# 直接开玩（Windows）
Tools\Godot.exe --path .

# 用控制台版跑（能看到日志输出）
Tools\Godot_console.exe --path .
```

引擎是 **Godot 4.7.2**，已在 `Tools/` 里。项目没有第三方依赖，也没有需要下载的资源。

---

## 怎么玩

你是**莫**。迷宫右下角有一扇「门」，走到那里就通关。

路上散落着两种东西：

- **偏旁**（火 刂 冫 工 石 风 艹）——**决定结局**的核心道具。每个偏旁都有「主动效果」和「携带代价」。
- **汉字**（模 漠 蟆 墓 暮 幕）——拾取即得**永久增益**，不占背包、不影响结局。

**关键抉择：偏旁带着走才有结局，但它会一路拖累你。** 你是要一路顺手，还是背着代价去换那个字？

### 操作

| 按键 | 作用 |
|---|---|
| `← ↑ → ↓` / `WASD` | 移动一格（1 步） |
| `F` | 拾取脚下的道具 |
| `1` / `2` | 使用第 1 / 2 格的偏旁（消耗 1 步） |
| `Q` / `E` | 丢弃第 1 / 2 格的偏旁 |
| `空格` | 提前结束本回合 |
| `R` | 重新开始 |
| `Esc` | 退出（结算画面） |

`工` 和 `风` 需要选目标：按 `1` 进入选择模式后，用 `←↑` / `→↓` 切换目标格，`Enter` 确认，`Esc` 取消。

### 规则速查

- 每回合 **3 步**，走完自动进入下一回合。
- 生命 **3 点**，归零即失败；有「墓」的话可以续命一次。
- 视野 5×5，带「暮」变 7×7。走到过的格子会留在地图上（灰色），没走过的看不到。
- 地形：**荆棘 / 火 / 水**踩上去扣 1 血；**树木**要花 2 步（只剩 1 步时过不去）；**障碍物**过不去，只能用「工」砸开。

### 结局

走到出口时，看背包里**最先拾取的那个偏旁**：

| 携带 | 结局 |
|---|---|
| 什么都没有 | **空** —— 莫还是莫，下面那个空始终空着 |
| 火 | **焚** |
| 刂 | **刃** |
| 冫 | **冰** |
| 工 | **筑** |
| 石 | **磐** |
| 风 | **漂** |
| 艹 | **野** |

带两个偏旁时，**先捡到的那个**定格成结局，另一个作为「双生」尾声出现。也就是说：**同一个莫，只能填一次。**

## 代码结构

```
project.godot          项目配置，Data 作为 autoload
scenes/main.tscn       唯一的场景
scripts/data.gd        所有数据表：地块 / 偏旁 / 汉字 / 结局文案
scripts/game.gd        全部游戏规则（不依赖 UI，可无头跑）
scripts/board.gd       棋盘渲染：地块、迷雾、道具、玩家、选择光标
scripts/main.gd        UI 构建、键盘输入、调试参数
```

`game.gd` 是纯逻辑，没有任何 UI 依赖——所以能在 headless 下跑几千局测试。

## 开发者命令

参数写在 `--` 之后：

```bash
# 确定性单元测试：25 条断言，覆盖 8 种结局、死亡、续命、步数/背包/视野公式、免疫
Tools\Godot_console.exe --headless -- --unittest

# 压力测试 + 平衡测量：生成 N 张地图，每张跑 600 次随机操作
Tools\Godot_console.exe --headless -- --selftest=300

# 截图（可配 --scenario）
Tools\Godot_console.exe -- --autoshot=res://_shots/board.png --shot-frames=40

# 摆好场景再截图：board(默认) / items / target / status / ending / ending2
Tools\Godot_console.exe -- --scenario=ending --autoshot=res://_shots/end.png

# 把合成按键推进真实输入管线（验证 事件→viewport→_unhandled_input→游戏状态）
Tools\Godot_console.exe -- --trace-input --keys=right,right,down,f,1

# 打印当前状态
Tools\Godot_console.exe -- --keys=right --autoshot=res://_shots/x.png
```

### 测试结果（当前）

```
[unittest] 断言失败 0 条。PASS

[selftest] 跑了 300 局，失败 0 局。PASS
[selftest] 平衡 A 裸装直冲最短路：通关  61 / 死亡 239 / 未结束 0
[selftest] 平衡 B 裸装绕开危险：  通关 300 / 死亡   0 / 无路可走 0 / 未结束 0
```

每局 `selftest` 都会：检查出口可达 → 沿 BFS 路径真的走到出口（必须判胜并生成结局）→ 再跑 600 次随机操作（不许崩、血量不许变成负数）。

**平衡解读**：同一个玩家水平下，闷头直冲的存活率是 **20%**，认真绕开火/水的存活率是 **100%**。也就是说——
**这个游戏的难度来自「读懂地形」，而不是运气。** 而且这是「全程满血捡道具」的理想数据：真实玩家在迷雾里看不到完整地图，还要分心去捡偏旁。所以实际难度会更高，而偏旁自带的代价（石把你拖进火里、艹被火燎到）才是真正的风险来源。
如果嫌太简单，把 `game.gd::_generate_map()` 里的地形权重调高即可（荆棘 18 / 树 7 / 障碍 14 / 火 8 / 水 13）。

## 已知的实现取舍

策划文档里有两个效果依赖「地块寿命」这个未定义的机制，MVP 里换成了等价强度的替代：

| 位置 | 原文 | MVP 实现 |
|---|---|---|
| 偏旁「工」的携带代价 | 携带时走过地块提前一轮消失 | 走过的地块留下**瓦砾**，再次经过多花 1 步 |
| 汉字「幕」的效果 | 走过地块存在时间 +1 回合 | **荆棘不再对你造成伤害**（帷幕遮住尖刺） |

这两处都在 `scripts/data.gd` 里用注释标了「代策划」，等策划回来确认。详见 `MVP设计文档.md` 第 9 节。
